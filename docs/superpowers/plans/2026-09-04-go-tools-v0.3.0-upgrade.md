# go-tools v0.1.0 → v0.3.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump the template-pinned `go-tools` dependency from v0.1.0 to v0.3.0 in generated Hertz/Kitex projects, and wire the new `Insecure` field on `JaegerOption`/`ObservabilityConfig` through so generated dev environments keep their current plaintext-gRPC behavior instead of silently switching to TLS and crashing on startup.

**Architecture:** This is a mechanical, contract-sensitive template change: two version-pin string literals (one in Go generator code, one in an embedded YAML template) move from v0.1.0 to v0.3.0; three existing `ObservabilityConfig{...}` construction sites gain one additional field each, sourced from a struct already in scope (no new plumbing); two dev-config templates gain an explicit `Insecure: true` default. Golden fixtures and docs follow.

**Tech Stack:** Go 1.25+ (ncgo CLI itself), embedded YAML templates (`text/template` via ncgo's own template engine), golden-file testing.

**Spec:** Issue [#95](https://github.com/byx-darwin/ncgo/issues/95) (design confirmed in chat via superpowers:brainstorming bounded path — no separate design doc file for this bounded task).

## Global Constraints

- Target `go-tools` version: **v0.3.0** (both `go-common` and `go-framework`; `go-middleware` stays v0.1.0 — unchanged, out of scope).
- Generated project `go.mod` must still declare `go 1.26.5` — unchanged, do not touch.
- `Insecure` field is **passed through** at the 3 non-dev construction sites (sourced from existing in-scope config struct), and **hardcoded `true`** only at the 2 hertz dev-config defaults (`conf_go.yaml`, `conf_dev_yaml.yaml`). kitex has no dev jaeger block today — leave untouched.
- Contract-sensitive surfaces touched: scaffold templates (`internal/assets/_data/**`) and generator code (`internal/scaffold/mono/files.go`) — golden tests MUST be regenerated and diffed per `.claude/rules/go.md` §7 and §9.
- Docs (English + Chinese) must stay aligned per `CLAUDE.md` and `.claude/rules/agent-engineering.md` §8.

```go
// writeKitexGoMod pre-writes the project go.mod for a kitex scaffold so the
// generated module pins `go 1.26.5` and requires the go-tools modules at
// v0.3.0. The kitex tool only runs `go mod init` when go.mod is absent (which
// leaves the go-tools versions unpinned until `go mod tidy` resolves them);
// when go.mod already exists with a matching module path, kitex reuses it
// as-is and skips its own init. This mirrors the Hertz layout.yaml go.mod
// entry so the version is template-locked and reproducible. `go mod tidy`
// (run later) preserves these directives and only appends the kitex-runtime
// requires; go-middleware is added by tidy when WithDatabase imports it.
func writeKitexGoMod(dir, module string) error {
	body := fmt.Sprintf("module %s\n\ngo 1.26.5\n\nrequire (\n\tgithub.com/byx-darwin/go-tools/go-common v0.3.0\n\tgithub.com/byx-darwin/go-tools/go-framework v0.3.0\n)\n", module)
```

In `internal/assets/_data/hertz/layout.yaml`, update the go.mod block (lines 85-92):

```yaml
  - path: go.mod
    delims: ["{{", "}}"]
    body: |-
      module {{.GoModule}}

      go 1.26.5

      require (
          github.com/byx-darwin/go-tools/go-common v0.3.0
          github.com/byx-darwin/go-tools/go-framework v0.3.0
      )
```
