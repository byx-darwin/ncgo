# Design: fix `ratelimit_usecase.yaml` update_behavior regression (Issue #117)

## Context

Issue #117 reports that `make update` (which invokes the vendored `kitex
-template-dir template/kitex-template ...` binary directly) silently
overwrites hand-written files in a downstream `services/authority` project
after an unrelated proto edit. Several unrelated files were reported as
reverted: DB schema/query files, `internal/usecase/rulecenter/usecase.go`,
casbin config/tests, a `redis.go` helper, and `main.go`'s defer wiring.

## Investigation

Reproduced empirically: scaffolded a fresh `ncgo new --kind kitex --preset
rule-center --db postgres` project, hand-edited `internal/usecase/rulecenter/usecase.go`
and `internal/db/migrations/000001_init.sql`, then ran `make update`.

Result:
- `usecase.go` was reverted (regression confirmed).
- `000001_init.sql` was left untouched (its `update_behavior: skip` worked
  correctly).

Read the vendored kitex source
(`github.com/cloudwego/kitex@v0.16.3/tool/internal_pkg/generator/custom_template.go`).
`update_behavior: skip` **is correctly implemented** by the kitex tool —
`commonGenerate`/`loopGenerate` check `util.Exists(filePath)` and skip
regenerating existing files when `Type == skip`. There is no mechanism-level
bug: the tool honors the field exactly as ncgo's own design doc
(`internal/assets/_data/docs/kitex/design-doc.zh-CN.md:598-600`) describes:
`cover` for generated shells, `skip` for files the user is meant to hand-edit
after initial scaffold (its own example is "writing business logic in
usecase.yaml").

The actual defect: `internal/assets/_data/kitex/kitex-template/ratelimit_usecase.yaml`
declares `update_behavior: { type: cover }`, while its own template body
says `// Code generated by ncgo rule-center preset. Edit business logic
here.` — directly contradicting the documented `skip` convention. The
generic (non-preset) `usecase.yaml` already correctly uses `skip`; the
rule-center preset's copy is the one outlier.

`ratelimit_handler.yaml` and `ratelimit_repository.yaml` are correctly
`cover` — their bodies only say "Code generated by ncgo rule-center
preset." (no "edit business logic here" invitation); they are thin
wiring/plumbing meant to always regenerate.

The remaining reported losses (casbin files, `redis.go` dead-code helpers,
`main.go` defer wiring, a `roles.is_super` column) do **not** reproduce in
ncgo's own rule-center preset — the base preset does not generate casbin
files or a `roles` table at all. These are downstream (`api-src`)
customizations layered on top of the `template/kitex-template/` directory
ncgo generates once; their `update_behavior` correctness is out of ncgo's
scope and must be fixed in that repo.

Bug 2 (line-api `rate_limit.go` not calling `joinRateLimitKey`) does not
reproduce in ncgo's own `internal/assets/_data/hertz/layout.yaml` either —
the function is both defined (line ~3283) and called (line ~3832) in
ncgo's canonical template. This is downstream drift, not an ncgo defect.
Per user decision, ncgo adds a preventive self-check only (no behavior
change) to guard against this class of drift being introduced into ncgo's
own templates in the future.

## Fix

1. `internal/assets/_data/kitex/kitex-template/ratelimit_usecase.yaml`:
   change `update_behavior.type` from `cover` to `skip`.
2. Regenerate golden testdata for the rule-center preset
   (`internal/scaffold/mono/testdata/mono-kitex-template-rulecenter/...`)
   via `-update-golden`.
3. Add a regression test (in `internal/scaffold/mono` or
   `internal/scaffold/template`) asserting that any rule-center preset
   template whose body invites hand-editing ("Edit business logic here")
   declares `update_behavior: skip`, to prevent this class of regression
   recurring.
4. Add a preventive test asserting `internal/assets/_data/hertz/layout.yaml`'s
   `joinRateLimitKey` (and similarly-shaped helper functions in that
   template) has both a definition and a call site in the rendered body,
   guarding against future edits reintroducing the Bug 2 drift pattern in
   ncgo's own template.
5. Comment on Issue #117 recording the investigation conclusion: casbin /
   redis.go / main.go / roles-table losses are downstream (`api-src`)
   template customizations outside ncgo's generated surface and need to be
   fixed there.

## Scope boundaries

- No CLI/MCP contract changes.
- No changes to `update_behavior` semantics or the kitex adapter's
  generator invocation — the mechanism works as designed.
- Casbin/redis/main.go/roles-table items are explicitly out of scope (not
  reproducible in ncgo's own templates).

## Testing

- `go test ./internal/scaffold/mono/... -run TestGenerateGoldenDefault -count=1`
  and rule-center-specific golden tests after `-update-golden`.
- New unit test(s) for update_behavior/business-logic-marker consistency
  and for the hz layout helper-function call-site check.
- `go build ./... && go vet ./... && go test ./... -count=1`.
