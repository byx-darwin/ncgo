# ncgo Agent Guide

## Purpose

This repository contains the `ncgo` CLI itself. It is not an application
generated by ncgo. Changes here can affect CLI users, MCP clients, embedded
templates, and every project generated from those templates.

Read `CLAUDE.md` for the fuller architecture overview. For end-user Agent
setup, see `docs/agent-quickstart.md` or `docs/agent-quickstart.zh-CN.md`.

## Repository Map

- `internal/cli/`: Cobra commands, flags, exit behavior, and text/JSON output.
- `internal/mcp/`: MCP tool schemas, handlers, sandboxing, and structured output.
- `internal/orchestrator/`: shared CLI/MCP workflows.
- `internal/scaffold/`: service, domain, infra, and template generation.
- `internal/assets/_data/`: embedded templates and generated-project docs.
- `internal/manifest/`: `.ncgo/manifest.yaml` and `ncgo.workspace` contracts.
- `internal/ai/`: `AGENTS.md`, Claude, Cursor, and project-context rendering.
- `internal/doctor/`, `internal/protolint/`, `internal/scan/`: validation.
- `docs/` and `specs/`: user workflows, contracts, and design decisions.

Do not scan `docs/superpowers/` by default. Read a file there only when a task,
issue, or commit explicitly points to it.

## Task Routing

| Change | Start here | Minimum focused validation |
| --- | --- | --- |
| CLI command or flag | `internal/cli/` | matching CLI tests and `--help` smoke |
| MCP tool or result | `internal/mcp/` | MCP schema, result, and error tests |
| Shared CLI/MCP behavior | `internal/orchestrator/` | orchestrator plus both entry points |
| Generated project output | `internal/scaffold/`, `internal/assets/_data/` | focused tests and golden/compile checks |
| Manifest/workspace format | `internal/manifest/` | round-trip and validation tests |
| Agent context | `internal/ai/`, `internal/scan/` | sync, preservation, and stale checks |
| User-visible workflow | English and Chinese docs | link and command verification |

## Contract-Sensitive Surfaces

Treat these as public contracts:

- CLI flags, defaults, exit codes, and text/JSON output;
- MCP input schemas, `content[0].text`, structured fields, and error behavior;
- manifest, workspace, template-package, and registry formats;
- generated paths, markers, anchors, and overwrite semantics;
- embedded templates and generated Agent instructions;
- English/Chinese documentation pairs.

When one of these changes, update implementation, tests, fixtures, and docs in
the same change.

## Source and Generated Ownership

Fix generators or embedded templates, not only their generated output.

- Edit `internal/assets/_data/` or scaffold code for downstream file changes.
- Update golden fixtures deliberately; do not make fixtures the source of truth.
- Preserve `ncgo:managed`, `ncgo:custom`, method, and wiring markers.
- Do not overwrite hand-authored files unless the command contract explicitly
  allows it and the user selected `--force`.
- Preserve unrelated user changes in a dirty worktree.

## Working Method

1. Read the relevant implementation, nearby tests, and originating issue/spec.
2. Identify affected contracts before editing.
3. Make the smallest change that satisfies the issue.
4. Run focused tests first.
5. Run broader validation proportional to the affected surface.
6. Update English and Chinese docs when behavior is user-visible.
7. Report tests run and any remaining risk.

For MCP or other mutating workflows, prefer read-only inspection and
`--plan`/`--dry-run` before writing whenever the command supports it.

## Validation

Focused examples:

```bash
go test ./internal/cli/... -count=1
go test ./internal/mcp/... -count=1
go test ./internal/ai/... -count=1
go test ./internal/scaffold/mono/... -count=1
```

Full pre-delivery checks:

```bash
go build ./...
go build .
go vet ./...
go test ./... -count=1
./scripts/smoke.sh
```

Template compile tests require the generator tools documented in
`CONTRIBUTING.md`. When a failure depends on a module proxy or another external
service, distinguish that from a product failure and record the environment.

## Definition of Done

- The issue acceptance criteria are demonstrably satisfied.
- Focused tests pass; broader checks were run when warranted.
- Public contracts remain compatible or the breaking change is documented.
- Generated outputs and golden fixtures match their source templates.
- English and Chinese user documentation remain aligned.
- No unrelated files or user changes were modified.
- The handoff lists validation performed and remaining risks.
