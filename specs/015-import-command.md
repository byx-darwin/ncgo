# ncgo import 命令设计

- 状态：Draft
- 关联：`specs/010-v1.0-plan.md` Phase 2 / P1-4

## 1. 问题

已有 hz/kitex 项目无法享受 ncgo 的 manifest、doctor、ai sync、MCP 等能力。用户需要手动创建 `.ncgo/manifest.yaml` 才能接入。

## 2. 方案

`ncgo import` 检测现有项目特征，反向生成 manifest。

### 2.1 命令接口

```bash
ncgo import --root .              # 自动检测项目类型
ncgo import --root . --kind hertz # 显式指定类型
ncgo import --root . --dry-run    # 仅预览，不写文件
```

### 2.2 检测逻辑

```
                      ┌─────────────┐
                      │ 检测 go.mod │
                      └─────┬───────┘
                            │
                  提取 module path
                            │
              ┌─────────────┴─────────────┐
              │                           │
         hertz 特征                  kitex 特征
    ┌─────────────────┐        ┌─────────────────┐
    │ router.go       │        │ handler.go       │
    │ router.Generated│        │ kitex server     │
    │ Register()      │        │ NewServer()      │
    │ hz 生成标记     │        │ kitex 生成标记   │
    └────────┬────────┘        └────────┬────────┘
              │                           │
              └─────────────┬─────────────┘
                            │
                    生成 manifest
```

### 2.3 检测规则

**Hertz 项目**：
- 存在 `router.go`，包含 `// Code generated by hz.`
- `router.GeneratedRegister()` 调用
- `internal/handler/` 目录结构

**Kitex 项目**：
- 存在 `handler.go`，包含 `// Code generated by kitex.`
- `svr := <service>.NewServer(...)` 调用
- `internal/handler/` 目录结构

**模块路径**：
- 从 `go.mod` 第一行提取

**服务名**：
- Hertz：从 `hz new --service` 参数残留或 idl 文件名推断
- Kitex：从 handler 注册的 service name 推断

**IDL 路径**：
- 搜索 `idl/` 目录（`.proto` 或 `.thrift` 文件）
- 优先 `idl/app/<name>.proto`

### 2.4 生成的 manifest

```yaml
ncgo:
  version: "0.1.0-dev"
  assets_version: "<current>"
mode: mono
module: github.com/acme/user-api    # 从 go.mod 提取
service:
  name: user-api                    # 推断
  kind: hertz                       # 检测
  with_database: false              # 默认，用户可手动改
  idl: idl/app/user-api.proto       # 检测或留空
infra: []
domains: []
generated_at: "2026-06-01T00:00:00Z"
# imported_from: hz                  # 标记来源
```

### 2.5 后续操作

`ncgo import` 成功后提示：

```
✓ Created .ncgo/manifest.yaml

Next steps:
  ncgo doctor                    # 检查项目健康状态
  ncgo ai sync                   # 生成 AI 上下文文件
  ncgo add infra redis --dry-run # 预览可选基础设施
```

## 3. 限制

- 只支持 mono 项目（micro 工作区的 import 更复杂，v0.8+）
- 不修改任何现有文件（只新增 `.ncgo/manifest.yaml`）
- 推断可能不准确，用户需手动检查生成的 manifest
- `--dry-run` 模式只打印，不写入

## 4. 测试

- 对 hertz 和 kitex 的 golden testdata 跑 import → 验证生成的 manifest 正确
- 对非 ncgo 项目（裸 Go 项目）跑 import → 验证正确报错
- 对已有 manifest 的项目跑 import → 验证拒绝覆盖
