# ncgo v1.0 计划

基于 2026-05-29 多维度分析（架构、安全、DX、产品战略）制定。

## 优先级定义

| 级别 | 含义 | 时间 |
|------|------|------|
| P0 | 阻塞 v1.0，必须修 | v0.6 |
| P1 | v1.0 前应该修 | v0.7 |
| P2 | 锦上添花 | v1.0 / 之后 |

---

## Phase 1 — v0.6：消债 + 安全加固（目标 4-6 周）

### P0-1：创建 `internal/orchestrator/` 共享服务层

**问题**：CLI（`internal/cli/`）和 MCP（`internal/mcp/`）各自重复编排逻辑。`runNewMono` 在 cli/root.go 和 mcp/tool_new.go 各写一遍。

**做法**：
1. 新建 `internal/orchestrator/` 包
2. 定义 `NewService(ctx, opts) (*Result, error)`、`AddInfra(ctx, opts) (*Result, error)` 等统一接口
3. CLI command 和 MCP tool handler 改为薄包装——只负责参数绑定和输出格式化
4. 先迁移 `new` → 验证 → 再迁移 `add infra/domain/rpc/bff/method/rule-center`

**影响文件**：
- 新建 `internal/orchestrator/new.go`, `add.go`, `doctor.go`, `export.go`
- 重构 `internal/cli/root.go`, `add.go`, `add_rulecenter.go`
- 重构 `internal/mcp/tool_new.go`, `tool_add.go`, `tool_domain.go`, `tool_rulecenter.go`

### P0-2：`infra/wire.go` 从字符串替换迁移到 `go/ast`

**问题**：`strings.Contains` + `strings.Replace` 修改 Go 源码，上游模板格式化变化即断裂。

**做法**：
1. 用 `go/parser` + `go/ast` 重写 `wire.go` 中的插入/替换逻辑
2. 保留 `// ncgo:wire:` 标记注释作为 AST 遍历的锚点
3. 用 `go/printer` + `go/format` 输出格式化代码
4. 补充测试：对每种 wiring 类型（logging、canary、redis、kitex server/client）写 golden test

**影响文件**：
- 重写 `internal/scaffold/infra/wire.go`
- 新建 `internal/scaffold/infra/wire_test.go`（目前无测试）

### P0-3：安全加固

1. **MCP frame 大小上限**：`internal/mcp/server.go` 的 `readFrame` 加 10MB Content-Length 上限
2. **MCP 路径沙箱**：所有 MCP 工具加 `validateProjectRoot()` 校验，确保 `root`/`dir` 在项目目录内
3. **compose.yaml 生产警告**：`internal/scaffold/shared/container.go` 生成的文件头加醒目的 "LOCAL DEVELOPMENT ONLY" 警告
4. **`.dockerignore` 敏感文件**：补全 `.env`、`*.pem`、`*.key`、`credentials` 排除
5. **Module path 校验**：`mono.go` 中用正则验证完整 Go module path 格式

### P0-4：解决 rulecenter 双路径

**问题**：`mono/files.go:117-133` 内联写 rule_center_client.go，`rulecenter/rulecenter.go:88-115` 又重复写同一个文件。

**做法**：mono preset 路径改为调用 `rulecenter.Add()`，删除内联写入逻辑。

### P0-5：NATS / Mongo / MinIO 去留决策

**问题**：README 和 PRD 中标记为 "deferred" 但未正式决定。

**做法**：二选一——
- 决定实现：补齐模板、测试、文档
- 决定移除：从 README/PRD 中删除占位，标记为 "will not implement"

## Phase 2 — v0.7：DX + 功能补全（目标 4-6 周）

### P1-1：CLI 自动补全

```bash
ncgo completion bash > /usr/local/etc/bash_completion.d/ncgo
ncgo completion zsh  > /usr/local/share/zsh/site-functions/_ncgo
ncgo completion fish > ~/.config/fish/completions/ncgo.fish
```

用 Cobra 内置 `GenBashCompletion`/`GenZshCompletion`/`GenFishCompletion`。

### P1-2：`ncgo new` 交互模式

缺 `--module` 时进入 TUI 提示流（用 bubbletea）：
```
? Service name: user-api
? Go module: github.com/acme/user-api
? Service kind: ( ) hertz  (•) kitex
? Database: (•) none  ( ) postgres
? Preset: (•) default  ( ) rule-center
```

### P1-3：补全 MCP 工具覆盖

当前 CLI 有但 MCP 无的命令：
- `ncgo_upgrade`（只读 `--plan` 模式即可）
- `ncgo_extract_domain`（`--dry-run` 模式，不加 `--apply`）
- `ncgo_export_templates`
- `ncgo_test_rate_limit_e2e`（`--plan` 模式）

`ncgo_version` 加结构化字段：`ncgoVersion`、`assetsVersion`、`buildRevision`、`buildTime`。

### P1-4：`ncgo import` 命令

从原始 hz/kitex 项目反向生成 `.ncgo/manifest.yaml`：
1. 检测 `hz new` 生成的 `main.go` / `router.go` 特征
2. 检测 `kitex` 生成的 `handler.go` 特征
3. 推断 module path、service name、kind、IDL 路径
4. 写入最小 manifest，后续可用 `ncgo ai sync` 补全上下文文件

### P1-5：Cobra `Example` 字段

每个 cobra.Command 补充 `Example` 字段，`--help` 输出带使用示例。

### P1-6：统一 `extract domain --json` → `--output json`

废弃 `--json` flag，迁移到 `--output text|json` 标准模式。过渡期两套 flag 都接受。

## Phase 3 — v1.0：稳定 + 发布（目标 4-6 周）

### P2-1：K8s 基础设施生成

`ncgo add infra k8s`：生成 Helm chart 或 Kustomize overlay，与已有 Dockerfile 对齐。

### P2-2：测试覆盖率提升

目标：关键包 80%+ 覆盖率。
- `internal/scaffold/infra/wire.go`（目前 0%）
- `internal/cli/` 补 `add method`、`add rule-center`、`export templates` CLI 测试
- `internal/mcp/` 补新增工具的端到端测试

### P2-3：文档审计

- 英文版补齐：canary、logging、i18n、proto-io、release docs
- `specs/examples.md` 补 `upgrade`、`extract domain`、`export templates` 示例
- 所有交叉引用链路检查

### P2-4：发布基础设施

- `CHANGELOG.md`
- SemVer 政策文档
- GitHub Release 自动化
- 二进制发布（goreleaser）

### P2-5：社区建设

- 写 "Why ncgo" 技术博客
- CloudWeGo 社区推广
- Good First Issue 标签 + 贡献者指南优化

## 不在此计划内的（v1.1+）

| 项目 | 原因 |
|------|------|
| Web UI / TUI 全功能界面 | 工作量大，先验证 CLI 用户基数 |
| 超越 Hertz/Kitex 的框架支持（gin、fiber） | 范围蔓延，先稳住核心生态 |
| 插件/扩展系统 | v2.0 级别功能 |
| 社区模板注册表 | 需要先有社区 |
| 运行时集成（Helm、服务网格） | P2-1 只做基础 K8s |
